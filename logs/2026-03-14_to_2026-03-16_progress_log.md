## Part 1: MNIST Task - RT Prediction Optimization

### 1.1 Baseline Problem (2026-03-14)

**Experiment**: Exp01 - Fixed Noise, 100 epochs

**Configuration**:
| Parameter | Value |
|-----------|-------|
| Time Steps | 20 |
| Normalization | Linear (min=0.296s, max=4.995s) |
| Epochs | 100 |
| Batch Size | 64 |
| Learning Rate | 0.001 |
| RT Supervision | Yes |
| Fixed Noise | True (noise_std=0.5, mask_p=0.4) |

**Results**:
| Metric | Model | Human | Ratio |
|--------|-------|-------|-------|
| RT Mean | 2.73s | 0.94s | **3.0x** |
| RT Std | 0.76s | 0.43s | - |
| Accuracy (correct) | 75% | 70% | - |
| Accuracy (human resp) | - | - | - |

**Critical Issue Identified**: Model RT is 3x larger than human RT.

**Root Cause Analysis**:
1. **Discretization Limitation**: With time_steps=20, model can only output 20 discrete RT values
2. **Output Range**: min output = 0.05 → 0.53s after denormalization
3. **Human RT min**: 0.296s, so model cannot produce fast enough responses

---

### 1.2 Solution Exploration (2026-03-15)

#### Experiment 02: Increase Time Steps to 100

**Configuration**:
- Time Steps: 100 (increased from 20)
- Epochs: 10 (quick test)

**Results**:
| Metric | Model | Human | Ratio |
|--------|-------|-------|-------|
| RT Mean | 1.59s | 0.94s | **1.69x** |
| RT Std | 0.29s | 0.43s | - |
| RT Correlation | -0.016 | - | - |

**Conclusion**: 
- ✅ RT ratio improved from 3.0x to 1.69x (43.5% improvement)
- ⚠️ Training is too slow (~15 hours for 100 epochs)

#### Experiment 05: Log Normalization (Breakthrough!)

**Configuration**:
| Parameter | Value |
|-----------|-------|
| Time Steps | 20 (same as baseline) |
| Normalization | **Log scale** |
| Epochs | 10 (quick test) |
| RT Supervision | Yes |

**Rationale**:
- RT distribution is right-skewed (typical for reaction times)
- Log normalization: `rt_norm = (log(rt) - log(rt_min)) / (log(rt_max) - log(rt_min))`
- Provides better resolution for low RT values

**Results**:
| Metric | Model | Human | Ratio |
|--------|-------|-------|-------|
| RT Mean | 1.01s | 0.94s | **1.08x** ✅ |
| RT Std | 0.59s | 0.43s | - |
| Accuracy | 16% | 70% | - |
| RT Correlation | 0.0021 | - | - |

**Key Finding**: Log normalization dramatically improves RT prediction!
- RT ratio improved from 3.0x to 1.08x (64% improvement)
- Training is fast (~4 it/s vs ~1.5 it/s for t=100)

#### Experiment 06: Time Steps = 50

**Status**: Stopped early

**Reason**: Exp05 (Log Norm) showed better results with faster training

**Issue**: Longer training caused model to become more conservative (slower decisions)

### 1.6 Key Learnings - MNIST Task

| Approach | RT Ratio | Training Speed | Status |
|----------|----------|----------------|--------|
| Baseline (t=20, linear) | 3.0x | Fast | ❌ |
| t=100, linear | 1.69x | Slow | ⚠️ |
| t=50, linear | ~1.5x (estimated) | Medium | Stopped |
| **t=20, Log Norm** | **1.08x** | **Fast** | ✅ **Best** |

**Conclusions**:
1. **Log normalization is crucial for RT prediction** - matches RT distribution better
2. **Time steps affect resolution but not as much as normalization method**
3. **Training speed matters** - Log norm with t=20 is 2.7x faster than linear with t=100
4. **Trade-off between accuracy and RT matching** - need balanced loss

## Part 2: VAM (Flanker) Task Development

### 2.1 Task Overview

**Task**: VAM Lost in Migration - Flanker task variant
- Identify the direction of the center bird
- Stimuli: Birds pointing in 4 directions (L/R/U/D) with flanker birds
- Behavioral Data: Human responses and reaction times

### 2.2 Data Preprocessing Module (2026-03-15)

**File**: `src/data/preprocess_vam_data.py`

**Features**:
- `VAMDataset` class for loading VAM data
- Stimulus image generation from bird graphics
- Log normalization for RT (consistent with MNIST approach)
- Support for multiple users and trial filtering

**Dataset Statistics**:
- Users: Multiple (configurable)
- Max trials per user: 25,000
- RT filter: 0.2s - 5.0s
- Image size: 128x128 (3 channels)

**Key Components**:
```python
DIRECTION_MAP = {'L': 0, 'R': 1, 'U': 2, 'D': 3}
LAYOUT_SPACERS = {
    0: [51, 0],    # horizontal line
    1: [0, 51],    # vertical line
    2: [51, 51],   # cross
    3-6: V shapes
}
```

**Derived Columns**:
- `target_dir`: Correct direction (0-3)
- `flanker_dir`: Flanker direction (0-3)
- `response_dir`: Human response direction (0-3)
- `correct`: Whether response matches target
- `congruency`: Whether flankers match target (0=congruent, 1=incongruent)
- `rt_normalized`: Log-normalized RT

### 2.3 Training Script (2026-03-15)

**File**: `src/experiments/vam_convlstm/train_vam.py`

**Key Features**:

## Part 4: Technical Issues & Solutions

### 4.1 RT Distribution Mismatch

**Problem**: Model RT distribution does not match human RT distribution
- Human RT: Right-skewed (typical decision-making)
- Model RT: Nearly uniform/normal

**Solutions Attempted**:
1. ✅ Log normalization - Best improvement
2. ⚠️ Increase time steps - Slow training
3. 🔄 RT distribution loss (KL divergence) - In progress
4. 🔄 Skewness penalty - In progress

### 4.2 Noise Parameter Collapse

**Problem**: Learnable noise parameters collapsed to near 0
- `noise_std` → 0.0004
- `mask_p` → 0.3 (initial value)

**Analysis**: Model learned to minimize noise, not use it meaningfully

**Solutions**:
1. Use fixed noise parameters
2. Add minimum noise constraint (`min_noise_std`)
3. Regularization on noise parameters

### 4.3 Accuracy-RT Trade-off

**Problem**: Longer training improves accuracy but increases RT ratio
- Model becomes more conservative over training

**Solutions**:
1. Balanced loss with RT weight
2. Speed penalty
3. Early stopping based on RT ratio
